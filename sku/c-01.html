What it is

Compliance architecture, not a compliance program.

C-01 is a reference architecture for systems that touch the Bulk Electric System. It tells you where CIP controls live in your architecture, how to categorize BES Cyber Assets defensibly, how to handle BCSI without leaking it through audit logs, and how to design evidence collection so a CIP auditor can complete a sample test without a forensic exercise.

C-01 does not run the program. It does not perform the categorization for you. It defines the architecture-level patterns that make compliance work tractable instead of perpetual scramble.

Problem & boundary

What C-01 solves — and what stays in your hands.

What C-01 solves

CIP compliance is run as a perpetual project at most utilities because the architectural patterns that should make it routine were never formalized. C-01 formalizes them.

  • BCSI leaks through audit logs because evidence-collection design wasn't done.
  • Categorization disagreements between IT, OT, and compliance because the inheritance rules live in someone's head.
  • Audit findings on documentation completeness because templates differ across teams.
  • Architectural drift between CIP scope and reality because there's no living model of what's in scope.

What C-01 deliberately excludes

C-01 is the architecture. It is not the program, the implementation, or the certification.

  • Performing the BES Cyber Asset categorization for your assets (you do this, using the templates).
  • Running your CIP program day-to-day or staffing your CIP SMEs.
  • Implementing the technical controls themselves (firewall config, IAM, patch management).
  • Conducting your CIP audit or representing you to NERC / WECC / SERC / TRE / MRO / NPCC / RF / SPP-RE.
  • Compliance for non-CIP standards (PRC, COM, EOP, IRO, MOD, TOP, etc.) — out of scope for v1.
CIP coverage

What's mapped, at what depth

All CIP standards in the current enforceable version are covered. Depth varies by standard — some are predominantly architecture (CIP-005, CIP-007, CIP-010, CIP-011), others are predominantly process (CIP-003, CIP-004). The mapping calls this out explicitly so you know what you're getting.

Architecture-heavy (deep coverage)

  • CIP-002 — BES Cyber System Categorization
  • CIP-005 — Electronic Security Perimeters
  • CIP-007 — System Security Management
  • CIP-010 — Configuration Change Management & Vulnerability Assessments
  • CIP-011 — Information Protection (BCSI)
  • CIP-013 — Supply Chain Risk Management
  • CIP-014 — Physical Security (architecture interface only)

Process-heavy (touch coverage)

  • CIP-003 — Security Management Controls
  • CIP-004 — Personnel & Training
  • CIP-006 — Physical Security of BES Cyber Systems
  • CIP-008 — Incident Reporting and Response Planning
  • CIP-009 — Recovery Plans for BES Cyber Systems
  • CIP-012 — Communications between Control Centers

Build status & open questions

What's still being decided

  • Upper-band pricing Listed band is $25K – $35K. The Customer Voice and Skeptical Utility CIO disagree on whether the top of the band is conservative given the budget category this hits. First three live conversations resolve it.
  • CIP-014 architecture coverage Physical security has a narrow architecture interface (CCTV, access control, intrusion detection). v1 covers the interface only; the question is whether v1.1 should extend deeper.
  • NIST CSF crosswalk completeness Full crosswalk vs. the subset that most utilities run as overlay. Trade-off: completeness signals seriousness vs. shipping speed.
  • Supply chain (CIP-013) depth Architecture patterns for supply-chain risk vs. process documentation only. Leaning toward architecture patterns with explicit handoff to procurement.
  • WECC / SPP-RE / TRE regional variations Regional Entity-specific interpretation differences across CIP. Ship a baseline in v1 with explicit "RE-specific guidance" sections to be expanded in v1.1.
